# PowerShield-FL

**A Privacy-Preserving, Communication-Efficient Federated Learning Framework for Electricity Theft Detection**

[![Python 3.10+](https://img.shields.io/badge/python-3.10%2B-blue)](https://www.python.org/)
[![PyTorch](https://img.shields.io/badge/PyTorch-2.x-red)](https://pytorch.org/)

> **Dataset status:** the committed/executed experiments use **SYNTHETIC DEMO DATA** generated by the project. Every number in this README was measured by an actual local run and saved under `results/`. Synthetic results demonstrate that the software works; they are not evidence about a real utility's theft rate.

## Abstract

Electricity theft (non-technical loss) is costly and difficult to detect without centralising sensitive smart-meter data. PowerShield-FL investigates:

> Can a lightweight, privacy-preserving, communication-efficient Federated Learning framework detect electricity theft effectively while reducing computational and communication overhead and handling heterogeneous client data?

The framework compares:

| Track | Method | Purpose |
|---|---|---|
| A | Centralized Logistic Regression, Random Forest, MLP, Lightweight MLP, CNN-LSTM | Centralized baselines with pooled data |
| B | Standard FedAvg | Federated baseline, no privacy/compression |
| C | **PowerShield-FL** | Lightweight MLP + clipping/Gaussian noise + int8 update quantization + adaptive aggregation + explainability |

## Problem Statement

Traditional theft detection centralises raw consumption records, violating consumer privacy and creating a single high-value data target. Federated Learning keeps raw records at clients, but standard FedAvg still has problems: it sends large float32 updates, weights unreliable clients equally, and offers no explanation for a theft alert.

## Objectives

1. Detect theft collaboratively without transmitting raw consumption sequences.
2. Use a small CPU-friendly model.
3. Reduce measured communication bytes.
4. Handle non-IID clients with different sizes and theft ratios.
5. Use adaptive client weighting (size × quality × reliability × class balance).
6. Produce model-derived explanations (SHAP, permutation importance, gradient×input).
7. Compare detection, communication, training time, memory, and scalability honestly.

## Existing System vs Proposed System

**Existing / baseline:** standard FedAvg with a heavier model, no update protection, no compression, sample-count-only weighting, and no explanation layer.

**Proposed PowerShield-FL:**

| Component | Implementation |
|---|---|
| Local model | `LightweightMLP` (10,689 parameters, <45 KB checkpoint) |
| Privacy | L2 update clipping + Gaussian noise; optional simulated additive-mask secure aggregation |
| Communication | int8 quantization by default; top-k and top-k+quantization implemented and measured |
| Aggregation | adaptive weights from sample share, local validation quality, update reliability, class balance |
| Explainability | SHAP KernelExplainer, permutation importance, gradient×input per prediction |
| Detection | NORMAL / POTENTIAL_THEFT / UNCERTAIN with threshold tuned on validation only |

## Architecture

```text
Electricity dataset (real loader or SYNTHETIC DEMO DATA)
        ↓
Consumer-level split FIRST (train / validation / test)
        ↓
Cleaning → train-fitted imputation/outlier bounds/scaler → window features
        ↓
Client simulation (IID or non-IID Dirichlet; raw data stays local)
        ↓
Local LightweightMLP training → ClientUpdate (delta + aggregate statistics only)
        ↓
Privacy layer: clip → Gaussian noise → optional simulated secure aggregation
        ↓
Communication layer: compress + measure actual serialized bytes
        ↓
Server: FedAvg or adaptive weighted aggregation
        ↓
Global model → thresholded detection → explanations
        ↓
Dashboard + reports + figures + tables
```

## Dataset

### Default: synthetic demo

`data/source: auto` uses a real dataset in `data/raw/` when one is present; otherwise it generates 240 consumers × 180 days × 48 half-hourly readings with configurable theft patterns. Every artifact is labelled **SYNTHETIC DEMO DATA**.

Quick-mode measurements from the final run:

| Statistic | Value |
|---|---|
| Consumers (train/val/test) | 156 / 36 / 48 |
| Window samples (train/val/test) | 8,736 / 2,016 / 2,688 |
| Engineered/block features | 133 |
| Raw rows | 2,073,600 |
| Raw missing values | 4,244 |
| Raw duplicate rows | 0 |
| Train-window theft ratio | 8.08% |
| Test-window theft ratio | 6.03% |
| Split unit | consumer (no consumer appears in two splits) |

Non-IID quantity skew moves whole consumers between clients; it never thins or drops training windows. The final quick partition covers all **8,736** training windows exactly once. Client sizes are `[2016, 3640, 336, 2408, 336]`; `client_03` contains 43 consumers and zero theft windows, which exercises the single-class quality fallback.

### Real data

Supported loaders:

- **SGCC**: put `data.csv` + `label.csv` in `data/raw/` (see `config/datasets.yaml`).
- **Long CSV**: `data/raw/readings.csv` with `timestamp`, `consumer_id`, `consumption` (plus a label source).
- **Generic wide CSV**: consumer ID, date, and hourly/half-hourly columns with a theft flag.

No real dataset is bundled or downloaded. If a real file is absent, the dashboard/report keeps saying the results are synthetic.

  enabled: true

### Federated comparison

| Method | Clients | Rounds | Precision | Recall | F1 | ROC-AUC | Time (s) | Total bytes |
|---|---:|---:|---:|---:|---:|---:|---:|---:|
| FedAvg | 5 | 8 | 1.0000 | 0.9877 | 0.9938 | 0.9973 | 15.51 | 3,453,520 |
| **PowerShield-FL** | 5 | 8 | **1.0000** | **0.9938** | **0.9969** | **0.9969** | **15.97** | **902,449** |

**Measured communication reduction: 73.87%** (actual serialized payloads, including headers and quantization metadata).

### Sweeps (4 rounds each; same partitions)

| Sweep | Setting | F1 | Validation F1 | Total bytes |
|---|---|---:|---:|---:|
| Privacy | off | 0.9907 | 0.9914 | 451,241 |
| Privacy | noise 0.001 | 0.9814 | 0.9885 | 451,222 |
| Privacy | noise 0.003 | 0.9814 | 0.9885 | 451,243 |
| Privacy | noise 0.006 | 0.9814 | 0.9885 | 451,242 |
| Communication | none | 0.9814 | 0.9885 | 1,726,760 |
| Communication | int8 quantize | 0.9814 | 0.9885 | 451,222 |
| Communication | top-k 20% | 0.9272 | 0.9767 | 700,440 |
| Communication | top-k + int8 | 0.9236 | 0.9738 | 451,227 |

Observation: dense int8 quantization preserved the 4-round validation/test utility while cutting bytes by 73.87% relative to uncompressed communication. Top-k sparsification reduced test F1 in this setup. The privacy sweep does **not** show a monotonic F1 decrease; no privacy-degradation claim is made from these single-seed runs. Single-release epsilon estimates for the nonzero noise settings are 4,844.81 (0.001), 1,614.94 (0.003), and 807.47 (0.006); these do not include composition across rounds.

## Evaluation

- **Detection:** accuracy, precision, recall, F1, ROC-AUC, PR-AUC, confusion matrix.
- **Communication:** actual serialized upload/download bytes per round, total bytes, reduction vs FedAvg.
- **Computation:** wall time, inference latency, RSS/peak memory, parameter count, model size.
- **Privacy:** clipping/noise configuration and a **single-release** epsilon estimate — not an end-to-end DP guarantee.
- **Protocol:** consumer-level split first; train-only fitting; threshold tuned on validation and frozen for test.
- **Statistics:** multi-seed mean/std/CI and paired tests are implemented; the executed suite has one seed, so it honestly reports `STATISTICAL TEST NOT RUN — fewer than 2 paired seeds`.

## Limitations

1. **Synthetic data only** in the executed results; no real SGCC/IRISE dataset is bundled or claimed.
2. Simulated clients, not a real network deployment.
3. Secure aggregation is an additive-masking simulation, not cryptographic secure aggregation.
4. Epsilon is a single-release estimate without composition across rounds; no formal end-to-end DP guarantee is claimed.
5. One seed in the executed quick suite; no statistical significance claim.
6. Full mode was configured but **NOT RUN** on this CPU-only host.
7. Wall time/memory are machine-specific.
8. Top-k compression reduced F1 in this setup; int8 quantization was selected as the default from measured validation utility.
9. CNN-LSTM is a lightweight research baseline and may be under-trained relative to its capacity.

## Future Scope
